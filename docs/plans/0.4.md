# Plan: 0.4 · Overview, gestures & apps

**Status: spec, waiting for sign-off.** No 0.4 code is written until it's
signed off. Once it is, this file is the whole of 0.4; what each part ends
up as is added under "As built" in its section.

Branches: `v0.4-release` (off `v0.3-release`); this spec on `v0.4/spec`;
each part below on its own `v0.4/<part>` off `v0.4-release`. Roadmap
milestone: 0.4 · Overview, gestures & apps.

## Scope rule

0.3 grew through seven alphas because fixes, changes and small additions
kept getting pulled in. 0.4 doesn't:

- **0.4 is exactly the parts below.** After sign-off nothing new is added.
- **While building 0.4,** only bugs in 0.4 work and real breakages get
  fixed. Anything else (an idea, polish, "while I'm here") goes in
  [Parked](#parked) at the bottom of this file, and becomes an issue for
  0.5 or later when 0.4 ships.
- **Bugs in shipped 0.3 features** are fixed on `v0.3-release` as 0.3.x
  releases and merged forward into `v0.4-release`, never fixed inside a
  0.4 branch.
- **Each part starts with its Figma frames** (file `YFCi8Ed5t2jySVi1zFnKbP`),
  approved before any code.
- **Done** means every part is built with UI tests (headless
  `make ui-test`) and passes `make check`. From then on alphas take fixes
  only, and 0.4.0 ships after one week of daily use with no new bugs.

## Answers (2026-11-14)

- **Theme:** "Overview, gestures & apps": the overview and gestures from
  the 0.3 roadmap, plus four apps of WhiteRose's own.
- **Overview:** both styles, GNOME-style and niri-style, picked in
  Settings (or off).
- **Apps:** a task manager, a disk imager, clocks and a calculator.
- **Animations:** 0.4 needs a shared animation core in the compositor
  (gestures, overview, workspace switch). Curves, open/close animations
  and the battery switch stay in 0.5.
- **Everything optional:** each feature has its own setting; an update
  from 0.3 changes nothing the user already uses.
- **Branching:** `v0.4-release` off `v0.3-release`; 0.3 only gets fixes
  from now on.

## Decided while planning

### Everything optional

Light features are on by default, heavy ones off.

| Feature | Setting (`daemon/internal/store/keys.go`) | Default |
|---|---|---|
| Overview | `overview.style`: `off` / `gnome` / `niri` | `gnome`, on its own key (SUPER+W) |
| Overview on SUPER tap | `overview.superTap` | off: a SUPER tap stays the launcher |
| Workspace strip | `bar.workspaceStyle` gains `strip` | `dots`, as now |
| Strip previews | `bar.workspacePreviews` | off |
| Workspace slide | `animations.workspaceSwitch` | on |
| Gestures | `gestures.*` (one entry per gesture: an action or `app`) | on, with the mapping in part 2 |
| Activities | `activities.enabled` | off |
| Apps | ordinary apps, hidden like any other app | installed |

Settings pages: Settings › Windows › Overview, Settings › Top bar (the
strip), Settings › Mouse & touchpad › Gestures (in the pattern of
`shell/settings/modules/mouse/Page.qml`), and Settings › Activities, a new
module (`core: false`). A shell feature checks its own key, not the
`settings.modules.disabled` list.

### Keys

- **SUPER+W** opens and closes the overview (free today).
- **SUPER+SHIFT+A** cycles activities and holding it shows the picker.
  The plan said SUPER+Q, but that closes a window and stays that way.
- Both are in the keybinding catalog (`keybind.rs` `CATALOG`), so they
  can be changed in Settings › Keyboard and show on the SUPER+K sheet.

### Apps

Apps 7 to 10 don't depend on parts 1 to 6 and can be built in between.
Each one needs the packaging touchpoints: `apps/Cargo.toml` members,
`packaging/build.sh`, a `.desktop` file and icons, `Makefile`
`dev-apps` / `dev-apps-remove`, and `shell/Report.js` `ownApps`.

## Parts, in build order

### 1. Animation core (compositor)

Branch `v0.4/animation-core`.

- One shared animation system in the compositor: a value, a duration and
  an easing, driven by the frame clock. `render.rs` keeps redrawing while
  any animation runs, and stops when none does (no idle wake-ups).
- It replaces the one-offs: the scratchpad slide (`render.rs`
  `sliding_pad`, `scratchpad.rs` `Slide`), the tab strip (`tab_strip.rs`
  `Anim`) and the pointer shake (`shake.rs`, armed in `drm.rs`).
- Gesture-driven values: the fingers set the value directly, and on
  release a spring takes it to its end. 1:1 swipe and pinch need this.
- A workspace switch slides, built on it; `animations.workspaceSwitch`
  turns it off.
- 0.5 builds on it (curves, open/close animations, the battery switch).
  None of that is in 0.4.

**As built** (2026-11-15, three commits; described in ARCHITECTURE.md,
"Animations"):

- `anim.rs`: `Value` (still, timed `Tween` with a `Curve`, driven by
  the fingers, or a critically damped `Spring` on release that keeps
  the fingers' speed). Unit-tested without a clock.
- Frames: `WhiteRose::animating()` is the one check. On DRM the vblank
  draws the next frame, or a one-refresh timer when a frame had nothing
  new (this replaced shake's own timer). Nested, the host paces them.
- The scratchpad slide, the tab strips and shake run on it. A
  scratchpad slide turned round now takes its share of the 150 ms from
  where it is (eased), instead of from its linear progress.
- Workspace slide: 250 ms, eased out, a later workspace in from the
  right. Only the drawing moves; the old workspace's windows are drawn
  from where they were hidden. Switching back mid-slide turns it round.
  Fullscreen windows slide like the others (the bar shows over them
  while it slides). The old workspace's tab strips go at once.
- Setting: `animations.workspaceSwitch`, "Slide when switching" in
  Settings › Windows › Workspaces (Figma "Settings - Windows · slide
  when switching").

### 2. Touchpad gestures

Branch `v0.4/gestures`.

- Gestures are caught in `compositor/src/input.rs` (a gesture's begin
  event has `fingers()`). A bound gesture is used by the compositor; any
  other gesture still goes to the app, as it does today.
- Defaults (three fingers are the desktop's):
  - 3-finger swipe left / right: previous / next workspace, 1:1.
  - 3-finger swipe up, or pinch in: open the overview.
  - 3-finger swipe down: close the overview.
  - 3-finger drag: move the window under the pointer. Off by default.
  - 2-finger and 4-finger gestures go to apps unless bound.
- Settings › Mouse & touchpad › Gestures: each gesture → an action from
  the keybinding catalog, or "Pass to app". Bound gestures show on the
  SUPER+K sheet.

**As built** (2026-11-16; described in ARCHITECTURE.md, "Touchpad
gestures"):

- Settings: `gestures.bindings` (one map, `"<fingers>-<gesture>"` to an
  action; the spec's `gestures.*`) and `gestures.dragWindow`.
- The overview's gestures (swipe up, swipe down, pinch in) are Pass to
  app until part 3 adds the overview's actions and makes them their
  defaults.
- Three-finger drag is the compositor's (SUPER+drag's move), not
  libinput's three-finger drag; with it on, the three-finger swipes take
  four fingers, and the four-finger swipe rows are greyed.
- A gesture is held until it can be told apart only when something with
  that many fingers is bound; otherwise it reaches the app at once.
- Shortcuts that are a range of keys (workspace 1–9, arrows) and
  scratchpads can't be put on a gesture.
- The SUPER+K sheet shows bound gestures under the desktop's shortcuts
  (same width as before).

### 3. Overview, GNOME-style

Branch `v0.4/overview-gnome`.

- Drawn by the compositor, live: every workspace's windows, scaled.
  Windows on hidden workspaces aren't in `space`, so they're drawn from
  `Workspaces::windows(ws)` with offscreen rendering as in
  `toplevel_export.rs` `render_window`.
- The current workspace's windows are laid out without overlap; a row of
  workspaces along the top. Drag a window to another workspace; click a
  window to focus it; Esc or the key closes the overview.
- Search on top, as a shell layer over the compositor's view: open
  windows, apps, and everything the launcher searches (files, settings,
  the calculator) through `shell/Search.js`. That's what lets the
  overview replace the launcher on a SUPER tap when `overview.superTap`
  is on.
- Opened by its key, a SUPER tap (opt-in) or a gesture; animated in and
  out with part 1, following the fingers when opened by a gesture.

**As built** (2026-11-16; described in ARCHITECTURE.md, "Overview"):

- Drawn without offscreen rendering: windows are scaled at draw time
  (`render_elements` at a smaller scale), so they're live without
  capturing anything. Hidden workspaces' windows in the row are drawn
  from where they were hidden, as the workspace slide does.
- The compositor draws the windows, the row and the outlines and takes
  the pointer; the shell (`OverviewView.qml`) draws titles, the close
  button and the search from the `overview` IPC event. Esc is the
  compositor's.
- The overview gestures (three fingers up, down, pinch in) are now the
  defaults, following the fingers; letting go 30% of the way (or with a
  flick) finishes it.
- Style offered Off and GNOME until part 4 added niri.
- No blur or wallpaper behind it in 0.4: a near-black backdrop.

### 4. Overview, niri-style

Branch `v0.4/overview-niri`.

- Zooms out on the workspaces as they are (tiles and floating windows
  where they're laid out), live. Drag windows between workspaces; click
  a workspace to go there.
- Shares the scaled drawing and the drag code with part 3; which one
  opens is `overview.style`.

**As built** (2026-11-16; described in ARCHITECTURE.md, "Overview"):

- The workspaces sit side by side (the way the workspace slide goes),
  half size, the current one in the middle with its neighbours showing
  at the sides; the strip moves with the workspace slide, so scrolling,
  the arrow keys and three fingers left or right all slide it.
- Each workspace shows its wallpaper (the background and bottom layers,
  scaled), as niri does.
- No search and no workspace labels: only the hovered window's title,
  under its workspace, and its close button. "Open with SUPER" opens it
  without a search when the style is niri.
- A click on a workspace's empty space goes there and closes the
  overview (GNOME's stays open to show it); Enter closes it onto the one
  in the middle.

### 5. Workspace strip

Branch `v0.4/workspace-strip`.

- `shell/Workspaces.qml` gains a `strip` style: one cell per workspace,
  showing its apps' icons.
- Hovering a cell shows a live preview (`shell/WindowPreview.qml`, as the
  dock uses), only when `bar.workspacePreviews` is on.
- Drag a window onto a cell to move it there. Windows already carry their
  `workspace` in the IPC `windows` event, so the strip needs no new IPC.

**As built** (2026-11-16; described in ARCHITECTURE.md, "Top bar"):

- What's dragged is an app's icon, from one cell to another: the shell
  only sees the pointer over the bar, so a window dragged by its title
  bar can't be dropped there (Parked).
- Two IPC additions after all: a `move_window` request (by id; the
  existing one moves only the focused window, and focusing a window on
  another workspace switches to it), and each window's `place` in the
  `windows` event, so a hidden workspace can be previewed where its
  windows are. Moving a window onto the workspace shown now shows it
  (the overview's drag only ever moved windows away from it).
- The preview is the whole workspace, not one window: each window drawn
  live where it is, with their titles under it. It shows after the
  pointer rests 350 ms, and moves straight to the next cell after that.

### 6. Activities

Branch `v0.4/activities`.

- An activity is its own 9 workspaces, dock pins, wallpaper, recent
  files, and per-workspace layout and snap-zone overrides. Activities are
  saved in the settings database. Open windows don't come back after a
  restart: session restore isn't in 0.4.
- Compositor: `Workspaces` becomes per activity (today it's one global
  set, `WORKSPACES = 9` in `state.rs`). The IPC workspaces event carries
  the active activity.
- A window belongs to one activity, or to all of them: a window rule
  action, and an entry in the window menu.
- Per-activity keys: `dock.pinned`, `wallpaper.current`,
  `windows.layout.workspaces` and `windows.snap.zones.workspaces` get an
  activity dimension. The default activity reads the existing keys, so
  0.3 settings carry over unchanged.
- Recent files: the daemon records which activity was active when a file
  was used (its own small store), since `recently-used.xbel` has no field
  for it, and filters by it.
- Switched from an island view or with SUPER+SHIFT+A. Nothing of this
  shows unless `activities.enabled` is on.

**As built** (2026-11-16; described in ARCHITECTURE.md, "Activities" and
"Window menu"):

- `Workspaces` stays one set: the current activity's is the one in use
  and the others are put aside and swapped in on a switch (with their
  tile layouts), so the code that reads the workspaces didn't change.
- The per-activity keys are one setting, `activities.overrides`; the
  default activity reads the plain keys. A new activity uses the
  default's pins, wallpaper, layouts and zones until it has its own.
- There was no window menu: one was added (an app's title bar
  right-clicked, or ALT+SPACE, which is also how the UI test opens it)
  with workspaces, activities and Close.
- The bar shows the current activity's name while activities are on.
- Switching activity is immediate, not slid: the workspace slide finds
  its windows through the current set of workspaces.
- A window on every activity keeps its workspace number: it comes along
  to that workspace in the other activity, which may not be the one
  showing there.
- Recent files are tagged from when the daemon starts; the launcher and
  the overview follow them, Files' own Recent view doesn't (Parked).

### 7. Task manager (new app, `apps/tasks`)

Branch `v0.4/tasks`.

- Rust + cxx-qt + `apps/kit`, laid out like Notepad (`apps/notepad`).
- **Apps & processes:** apps grouped by their scope
  (`compositor/src/app_scope.rs`), their processes under each; CPU,
  memory (`memwatch.OwnBytes`), disk and network per app. End (SIGTERM)
  and force end (`cgroup.kill`), through the watcher's `close()` in
  `daemon/cmd/whiterosed/memory.go`.
- **Performance:** graphs over time for CPU per core, memory, disks,
  network and GPU.
- **Memory protection:** which apps are protected and which are at risk;
  edits `memory.protected` (the same data as Settings › Apps › Memory).
- A new daemon op for the numbers (cgroup `cpu.stat` and `io.stat`,
  `/proc/<pid>/stat`, `/proc/net/dev`, the GPU from sysfs and DRM
  fdinfo), so the app and later bar widgets share it.

### 8. Disk imager (new app, `apps/imager`)

Branch `v0.4/imager`.

- **Write an ISO or IMG to a USB drive:** only removable drives are
  offered (Files' `places.rs`, `lsblk` / `drives()`). Confirmed by the
  drive's name and size. Written through a new `whiterosed image-root`
  pkexec helper (in the pattern of `apps-root`, its policy in
  `packaging/files/org.whiterose.apps.policy`, asked for in
  `shell/PolkitPrompt.qml` with the fingerprint). Shows progress, and
  verifies after writing (`apps/files/src/hash.rs`).
- **Several ISOs on one stick, with Ventoy:** install Ventoy onto a
  stick (a pinned Ventoy release, downloaded and checksum-checked the
  first time it's used), then add, remove and list the ISOs on it.

### 9. Clocks (new app, `apps/clocks`) and the island

Branch `v0.4/clocks`.

- Alarms, timers, a stopwatch and a world clock.
- Alarms and timers live in the daemon, so they go off with the app
  closed: a critical notification (`shell/Notifications.qml`) with a
  sound.
- The island, when idle, shows running timers, the stopwatch or the next
  alarm with the time left, as a countdown you can see at a glance.
  Clicking it opens the app.
- World clock: zones from tzdata; city search reuses the weather
  geocoding (`daemon/internal/weather`).

### 10. Calculator (new app, `apps/calculator`)

Branch `v0.4/calculator`.

- Standard and scientific, with history.
- Reuses `shell/Calc.js` (through the app's `.qrc`, as Notepad does for
  its JS), extended with the scientific functions. The launcher
  (`LauncherView.qml`, which calculates since 0.3) gets the same
  functions for free.

**As built** (2026-11-26; approved Figma board
[`188:3035`](https://www.figma.com/design/YFCi8Ed5t2jySVi1zFnKbP?node-id=188-3035)):

- Standard and scientific keypads, editable expressions, live results and
  copy; degrees/radians, inverse trigonometry, logs, powers and factorial.
- The shared, bounded `shell/Calc.js` parser is embedded in the app.
  Launcher expressions keep radians and their existing remainder operator;
  the app starts in degrees and its percentage key divides by 100.
- Private persistent history (latest 100 expression/angle pairs), with
  reuse, copy and clear. Preferences survive reopening; independent windows
  merge history writes under a lock.
- Kit controls, dark/light themes, a narrow-window history overlay and a
  scrollable keypad. Binary, launcher entry and icons are packaged.
- Approved Doto refinement (`191:3284`): bundled Doto for the expression
  and main result only; existing control/history fonts stay, and the
  keyboard-hint footer is removed.
- Tests cover parser safety and scientific maths, operand editing, history
  persistence and concurrent writes, and real keyboard/pointer/clipboard
  interactions in the UI.

## Not in 0.4

Session restore; workspaces per monitor; a changing number of
workspaces; downloading ISOs; reading a drive into an image; a
programmer calculator; startup apps and services in the task manager;
open/close animations, blur and curves (0.5).

## How each part is checked

Figma frames approved → code → headless `make ui-test` and `make check`
→ `make shots` for review → merged into `v0.4-release`.

## Parked

Things that turned up while building 0.4 and aren't in it. Each becomes
an issue for 0.5 or later when 0.4 ships.

- **Drop a window on the bar's workspace strip by its title bar** (part
  5): the compositor would need to know where the strip's cells are
  while it moves a window.
- **Files' Recent view per activity** (part 6): the launcher and the
  overview list only the current activity's recent files; Files' own
  Recent view (opened lately, or changed in the last two weeks) still
  lists every activity's.
